Now · simulation

  1. 1

    The customer submits an image
    The browser reads the text. This does not authenticate the receipt.

  2. 2

    Local storage
    The image and claim stay in this browser. They are not delivered to another computer.

  3. 3

    Review dashboard
    Compare the image and details; review duplicates, eligibility and recipient address. Request clarification or reject the claim.

  4. 4

    Approval → payout queue → result
    Try successful and failed demo payouts. The test balance increases only after simulated success.

Planned production system

  1. 1

    Secure submission
    Customer sign-in, consent and secure submission to a server.

  2. 2

    Private file storage and database
    Access restricted to authorized reviewers, with a defined retention period.

  3. 3

    Verification against a reliable source
    An image or QR code alone does not prove ownership, payment or eligibility.

  4. 4

    Dedicated reward wallet
    Review the exact address and MVXA amount, authorize the payout and obtain real Solana confirmation. Only then display a real transaction link.

An energy-based reward requires kWh data. A separate rule can use the amount paid; 10 test MVXA / EUR here is only an example, not a price or promised cashback.
